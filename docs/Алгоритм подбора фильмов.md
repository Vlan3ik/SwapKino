# Интеграция Gorse в рекомендательную систему SwapKino

## 1. Цель изменений

Текущая самописная система рекомендаций SwapKino заменяется на отдельный сервис **Gorse**.

Основная цель архитектуры:

* убрать тяжёлый расчёт рекомендаций из HTTP-запросов;
* отказаться от собственного `RankMovies`, `RecommendationProfileBuilder`, pgvector-ranking и текущего MMR;
* передать Gorse долгосрочное обучение предпочтениям пользователя;
* оставить SwapKino контроль над бизнес-логикой киноплёнок;
* использовать Redis для событий, сессий и быстрой выдачи;
* сделать `/feed` максимально лёгким.

Gorse уже построен по схеме retrieval → ranking: его worker-узлы заранее рассчитывают рекомендации пользователей и сохраняют результат в cache store, а server при запросе преимущественно читает готовый результат, исключает просмотренное и применяет fallback.

# 2. Целевая архитектура

```text
                         SWAPKINO

                  ┌───────────────────┐
                  │     Frontend      │
                  └─────────┬─────────┘
                            │
                            ▼
                  ┌───────────────────┐
                  │   SwapKino API    │
                  │                   │
                  │ Auth              │
                  │ Catalog           │
                  │ Reels             │
                  │ User actions      │
                  └──────┬─────┬──────┘
                         │     │
                  READ   │     │ WRITE
                         │     │
                         ▼     ▼
        ┌──────────────────┐  PostgreSQL
        │ Recommendation   │      │
        │ Gateway          │      │ Outbox
        └────────┬─────────┘      ▼
                 │          Redis Streams
                 │                 │
                 │                 ▼
                 │       RecommendationSyncWorker
                 │                 │
                 ▼                 ▼
             ┌───────────────────────────┐
             │           Gorse           │
             │                           │
             │ Master                    │
             │ Workers                   │
             │ Recommendation Server     │
             └─────────────┬─────────────┘
                           │
                     Gorse Cache
                           │
                         Redis
```

При этом существует второй Redis-контур:

```text
Redis Runtime SwapKino

├── события
├── текущие сессии
├── уже показанные фильмы
├── session intent
└── готовые deck'и киноплёнок
```

В production желательно использовать:

```text
redis-runtime
    → SwapKino

redis-gorse
    → Gorse cache
```

а не смешивать их в одном Redis.

Gorse поддерживает отдельные `data_store` и `cache_store`; Redis может использоваться как cache store.

# 3. Разделение ответственности

## SwapKino отвечает за продукт

SwapKino определяет:

* какие фильмы вообще доступны;
* что является хоррором;
* что является аниме;
* что входит в психологическое кино;
* какие киноплёнки существуют;
* ограничения контента;
* просмотренные фильмы;
* текущую сессию;
* API для frontend;
* данные TMDB.

## Gorse отвечает за персонализацию

Gorse отвечает на вопрос:

> Какие из подходящих фильмов вероятнее понравятся конкретному пользователю?

Gorse получает:

```text
Users
Movies
Feedback
```

и самостоятельно использует несколько источников кандидатов: collaborative filtering, item-to-item, user-to-user, non-personalized recommendations и ranking.

## Redis отвечает за скорость

Redis не является рекомендательным алгоритмом.

Он нужен для:

```text
асинхронных событий
+
готовых результатов
+
быстрой session-state
+
исключения повторных тяжёлых вычислений
```

# 4. От чего отказываемся в SwapKino

После перехода на Gorse больше не являются основой рекомендаций:

```text
RecommendationProfileBuilder
RecommendationEmbeddings
MovieRecommendationFeatures
UserTasteProfiles

собственный ANN через pgvector
собственный profileMatch
текущий Theme()
текущий Quality()
текущий MMR внутри RankMovies()
```

Тяжёлый `RankMovies()` также должен исчезнуть из `ApiController`.

Текущий код действительно выполняет ANN, загрузку жанров/keywords/people и in-memory ranking непосредственно при формировании feed.

Оставляем:

```text
TMDB Client
Catalog Warmup
Catalog Enrichment
MovieGenres
MovieKeywords
MoviePeople
UserMovieStates
UserActions
RecommendationImpressions
Redis Streams / Outbox
```

Enrichment особенно важен: именно здесь SwapKino уже получает TMDB keywords и credits, необходимые для классификации фильма.

# 5. Recommendation Gateway

Frontend никогда не обращается к Gorse напрямую.

Используется логическая прослойка:

```text
SwapKino API
      ↓
Recommendation Gateway
      ↓
Gorse
```

Это **не отдельный микросервис** на первом этапе.

Recommendation Gateway является внутренним модулем SwapKino API.

Его задачи:

```text
SwapKino UserId → Gorse UserId

Movie ID → Gorse ItemId

Reel → Gorse Category

обработка timeout/error

fallback

кэширование

преобразование ответа Gorse
```

Благодаря этому SwapKino не становится жёстко зависим от Gorse.

В будущем:

```text
RecommendationGateway
        │
        ├── Gorse
        ├── собственная ML-модель
        └── другой recommendation engine
```

можно менять без изменения frontend API.

# 6. Как фильмы попадают в Gorse

Gorse item поддерживает `Categories` для фильтрации рекомендаций и `Labels` для описания контента.

После полного TMDB enrichment:

```text
TMDB
 ↓
Movie
 ↓
genres
keywords
director
actors
language
country
year
 ↓
Theme Classifier
 ↓
Gorse Item
```

В Gorse передаётся примерно следующая логическая информация:

```text
Item

ID
type
themes

genres
keywords
director
actors
language
country
year
content tags
```

### Categories

Categories используются прежде всего для киноплёнок:

```text
theme:horror
theme:anime
theme:detective
theme:psychological
theme:space
```

Также:

```text
type:movie
type:series
```

### Labels

Labels используются для понимания похожести:

```text
genre:horror
genre:thriller

keyword:supernatural
keyword:haunted-house
keyword:ghost

director:...
actor:...

language:en
origin:US
```

На первом этапе можно использовать content tags.

Позже можно добавить embedding фильма: Gorse поддерживает item-to-item similarity как по tags, так и по embedding.

# 7. Главное изменение киноплёнок

## Gorse не определяет, является ли фильм хоррором

Это принципиально.

```text
              Theme Classifier SwapKino

Movie ──────────────────────────────→ theme:horror
                                      theme:space
                                      theme:psychological
```

После этого Gorse получает уже готовую категорию.

Запрос:

```text
Хоррор
```

превращается в логический запрос:

```text
recommend user X
category = theme:horror
```

Gorse REST API поддерживает фильтрацию recommendations по category.

Следовательно:

```text
HORROR CANDIDATES
       ↓
Gorse personalization
       ↓
HORROR RESULTS
```

Gorse не может заменить хоррор драмой только потому, что пользователь любит драмы.

# 8. Убираем неправильные киноплёнки

Не должны существовать как recommendation themes:

```text
90 минут
до 100 минут
новинки
популярное
сейчас смотрят
проверено временем
старые фильмы
мини-сериалы
сериальный марафон
недооценённые
```

Это обычные параметры каталога.

Например:

```text
"до 100 минут"
=
runtime <= 100
```

```text
"новинки"
=
releaseDate DESC
```

```text
"классика"
=
year < X
+
rating
```

```text
"недооценённое"
=
rating высокий
+
popularity ниже среднего
```

Для такого функционала запуск recommendation engine не нужен.

# 10. Keyword Registry

Нельзя выполнять поиск TMDB keyword каждый раз при создании ленты.

Должен существовать центральный:

```text
Theme Registry
```

Например:

```text
theme:horror

required genres:
Horror

boost keywords:
supernatural
ghost
haunted house
demon
possession
slasher
...
```

Во время разработки каждому canonical keyword один раз сопоставляется проверенный:

```text
TMDB Keyword ID
```

После этого IDs хранятся в конфигурации/БД SwapKino.

Таким образом ThemeClassifier работает полностью локально.

# 11. Theme Classification

Classification выполняется только при изменении Movie metadata.

```text
TMDB Details
      ↓
Catalog Enrichment
      ↓
ThemeClassifier
      ↓
MovieThemeMembership
      ↓
Gorse sync
```

Не во время открытия киноплёнки.

Можно хранить:

```text
Movie
Theme
Confidence
ThemeVersion
```

Например:

```text
Alien

horror          1.00
sci-fi          1.00
space           0.92
psychological   0.71
```

При изменении правил:

```text
ThemeVersion 4 → 5
```

background job пересчитывает membership.

# 12. Как Gorse будет строить рекомендации

Для общего `Для вас` Gorse использует весь допустимый каталог.

Для тематической киноплёнки используется тот же персональный pipeline, но с category filter.

Концептуально:

```text
                    GORSE

 Collaborative ───────┐
                      │
 Item-to-item ────────┤
                      │
 User-to-user ────────┤
                      ├── Candidate Pool
 Popular fallback ────┤
                      │
 Latest ──────────────┘
                      ↓
                   Ranker
                      ↓
             personalized list
                      ↓
             Category filtering
                      ↓
                Gorse Cache
```

Gorse поддерживает несколько recommender-источников и объединяет их перед ranking.

Для SwapKino на старте рекомендуется использовать **FM ranker**, а не LLM-reranker: Gorse поддерживает factorization-machine ranking как штатный вариант.

# 13. Feedback

Feedback должен быть нормализован.

| SwapKino action | Значение для Gorse      |
| --------------- | ----------------------- |
| impression      | read                    |
| swipe_right     | positive                |
| favorite        | strong positive         |
| rating 7–8      | positive                |
| rating 9–10     | strong positive         |
| more_like_this  | strong positive         |
| rating 1–5      | negative                |
| not_for_me      | strong negative         |
| less_like_this  | strong negative         |
| watched         | read                    |
| swipe_left      | read + session negative |
| rating 6        | neutral/read            |

Gorse позволяет отдельно конфигурировать positive, negative и read feedback types.

## Swipe left

`swipe_left` не должен становиться сильным постоянным dislike.

Он означает:

```text
не хочу этот фильм сейчас
```

Поэтому:

```text
Gorse:
read

Redis Session:
negative
```

А:

```text
not_for_me
```

отправляется в Gorse как полноценный negative feedback.

# 14. Асинхронная запись feedback

При пользовательском действии API не ждёт Gorse.

```text
Frontend

   ↓ POST /actions

SwapKino API

   ↓

PostgreSQL transaction

UserAction
UserMovieState
OutboxEvent

   ↓

HTTP 200/201 пользователю
```

После этого:

```text
Outbox
  ↓
Redis Stream
  ↓
RecommendationSyncWorker
  ↓
Gorse feedback API
```

Если Gorse временно недоступен:

```text
пользователь ничего не замечает
```

Событие остаётся доступно для повторной обработки.

# 15. Зачем здесь Redis Streams

Redis Stream разрывает прямую зависимость:

```text
User Request
     X
   Gorse
```

Вместо этого:

```text
User Request
     ↓
Database
     ↓
Event
     ↓
Worker
     ↓
Gorse
```

Это позволяет:

* переживать недоступность Gorse;
* обрабатывать события пачками;
* масштабировать worker'ы;
* делать retry;
* не увеличивать latency пользовательских запросов.

# 16. Как открывается киноплёнка

Первое открытие:

```text
GET /reels/horror/feed
```

Дальше:

```text
SwapKino API
     ↓
ThemeRegistry
     ↓
theme:horror
     ↓
RecommendationGateway
     ↓
Gorse:
user X
category theme:horror
N = 100
     ↓
100 готовых ID
     ↓
SwapKino filters
     ↓
Redis session layer
     ↓
сохраняем deck
     ↓
берём первые 20
     ↓
один запрос Movie Summary
     ↓
Frontend
```

Gorse server берёт заранее рассчитанные worker'ами рекомендации из своего cache store, поэтому тяжёлая персонализация не должна происходить заново на каждый `/feed`.

# 17. Последующие страницы

Самое важное для производительности:

**не обращаться к Gorse на каждой странице.**

Первый запрос получает, например:

```text
100 ID
```

Они кладутся в Redis:

```text
rec:deck:
user
session
theme
```

После этого:

```text
page 1 → Redis 1–20
page 2 → Redis 21–40
page 3 → Redis 41–60
```

Следовательно большая часть swipe-сессии вообще не обращается к Gorse.

---

# 18. Session Intent

Redis используется для краткосрочного поведения.

```text
rec:session:{id}:intent
```

Например пользователь в хоррор-ленте несколько раз отклоняет фильмы с:

```text
slasher
serial killer
gore
```

Session intent становится:

```text
slasher        negative
serial-killer  negative
gore           negative
```

При этом:

```text
horror
```

не уменьшается, потому что пользователь специально открыл Horror reel.

Оставшиеся 80 фильмов можно очень дешёво переставить.

Это **не новая полноценная рекомендательная система**.

Это небольшой session reranker поверх готового результата Gorse.

# 19. Роль Redis целиком

```text
                     REDIS

       ┌──────────────────────────┐
       │ Redis Streams            │
       │                          │
       │ async events             │
       │ retry                    │
       │ workers                  │
       └──────────────────────────┘

       ┌──────────────────────────┐
       │ Session State            │
       │                          │
       │ seen                     │
       │ intent                   │
       │ current deck             │
       │ cursor                   │
       └──────────────────────────┘

       ┌──────────────────────────┐
       │ Gorse Cache Redis        │
       │                          │
       │ precomputed recs         │
       │ neighbors                │
       │ ranking results          │
       └──────────────────────────┘
```

Gorse самостоятельно кеширует user/item neighbors, non-personalized results и итоговый output ranker для пользователей; кэш обновляется при изменении данных, конфигурации либо истечении срока.

Redis поэтому помогает не «лучше рекомендовать», а **не считать одно и то же снова и снова**.

# 20. Работа с просмотренными фильмами

Карточка становится `impression` только тогда, когда она действительно показана пользователю.

```text
film появился на экране
        ↓
impression
        ↓
Redis Stream
        ↓
Gorse read feedback
```

Gorse рекомендует сохранять read feedback для показанных пользователю items, чтобы исключать уже просмотренные рекомендации.

Дополнительно SwapKino хранит свои:

```text
UserMovieStates
RecommendationImpressions
```

как источник продуктовой аналитики.

---

# 21. Fallback

Gorse не должен быть единственной точкой, от которой зависит открытие киноплёнки.

Если Gorse недоступен:

```text
1. Redis session deck

если нет:

2. Redis cached theme deck

если нет:

3. локальный Theme Popular
```

Например для Horror заранее имеется:

```text
theme:horror:popular
```

Это простая глобальная подборка качественных Horror-фильмов.

Таким образом:

```text
Gorse down
≠
киноплёнки down
```

# 22. Хранилища

Рекомендуемая структура:

```text
PostgreSQL
│
├── swapkino
│
│   ├── Movies
│   ├── Genres
│   ├── Keywords
│   ├── Users
│   ├── Actions
│   └── Impressions
│
└── gorse
    ├── users
    ├── items
    └── feedback
```

И:

```text
Redis
│
├── redis-runtime
│
│   ├── streams
│   ├── sessions
│   └── decks
│
└── redis-gorse
    └── Gorse recommendation cache
```

**PostgreSQL SwapKino остаётся source of truth.**

Gorse является производной системой.

Если Gorse потерян:

```text
catalog + users + feedback
```

можно синхронизировать заново из SwapKino.

# 24. Основной результат архитектуры

После перехода тяжёлый request path:

```text
SQL graph
→ profile calculation
→ pgvector
→ ranking
→ MMR
→ response
```

исчезает.

Основной путь становится:

```text
Gorse cached IDs
+
Redis
+
20 Movie summaries
```

То есть сложность рекомендаций переносится туда, где ей и место:

```text
background workers
```

а пользовательский API занимается быстрым serving.

При этом границы ответственности становятся однозначными:

```text
Gorse
=
КОМУ ЧТО НРАВИТСЯ

ThemeClassifier
=
ЧТО ЯВЛЯЕТСЯ ХОРРОРОМ / АНИМЕ / ДЕТЕКТИВОМ

Redis
=
ЧТО НУЖНО ПОКАЗАТЬ БЫСТРО И ПРЯМО СЕЙЧАС

SwapKino API
=
КАК ЭТО ПРЕВРАТИТЬ В ПРОДУКТ
```

Именно эту архитектуру стоит брать как целевую при полном отказе от нынешней самописной рекомендательной системы.
